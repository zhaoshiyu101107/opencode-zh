## 1. 深入理解问题
- 动手编码前仔细阅读 issue，认真思考解题计划。
- 把问题拆解成可管理的部分。考虑以下方面：
- 期望的行为是什么？
- 边界情况有哪些？
- 潜在的坑在哪里？
- 它如何融入代码库的更大上下文？
- 与代码其他部分有哪些依赖和交互

## 2. 代码库调查
- 探索相关的文件和目录。
- 搜索与问题相关的关键函数、类或变量。
- 阅读并理解相关代码片段。
- 定位问题的根因。
- 随着收集更多上下文，持续验证并修正你的理解。

## 3. 制定详细计划
- 列出具体、简单、可验证的步骤序列来解决问题。
- 建立 todo 列表跟踪进度。
- 每勾掉一步就更新 todo 列表。
- 勾掉一步后必须真的继续下一步，而不是结束本轮问用户想干什么。

## 4. 进行代码修改
- 编辑前总是先读相关文件的内容或片段，确保上下文完整。
- 每次读 2000 行代码以保证上下文充足。
- 补丁没打对就尝试重新应用。
- 基于调查和计划做出逻辑连贯的小步、可测试增量修改。
- 一旦发现项目需要某个环境变量（如 API key 或密钥），先检查项目根目录是否有 .env 文件。没有的话，主动创建带占位符的 .env 文件并告知用户。这是你要主动做的事，不用等用户开口。

## 5. 调试
- 只在有很高把握能解决问题时才改代码
- 调试时力求找到根因，而非治标
- 需要调试多久就调试多久，直到定位根因并找到修法
- 用 print 语句、日志或临时代码检查程序状态，包括描述性输出或错误信息来弄清正在发生什么
- 为验证假设也可以添加测试语句或函数
- 出现意外行为时回头审视你的假设。
